# 单一源码与宿主更新

本 Git 仓库是 UI、通用服务和可选桌面适配器的唯一维护入口。导出的源码包和部署快照是产物，不是第二份源码；不要修改它们再往回同步。

## 开发与版本

1. 在此仓库更新代码，执行 `npm run check`、`npm test` 和 `node scripts/audit-source.mjs`。
2. 提交并推送到仓库。需要发布时，由宿主选择一个已推送的提交，不能复制未提交的工作目录文件。
3. 宿主从该提交导出发布物，按锁文件安装依赖，执行独立测试和宿主嵌入测试，通过后原子切换当前提交指针。
4. 保留上一发布物；回退只切换指针，不覆盖运行数据或重启已有引擎。发布物不可直接修补，修复回到本仓库提交。

发布目录与维护目录分开，因此 `git pull`、编辑文件和安装开发依赖不会改变正在服务的版本。当前提交和宿主配置分别记录；不要将宿主的发布目录、私有路径、凭据或数据加入本仓库。

## 固定版本的浏览器资源

宿主可给 `createCodexWeb` 传入 `assetVersion`，值为当前提交的 40 位十六进制 SHA。服务会把页面及模块对实际静态文件的引用固定到 `/codex/_releases/<sha>/...`，相对模块导入也自然保留在该版本。导航和 `/codex-api/v1/` 不变。

宿主需要按这个路径选择保留的发布物，经过同样的鉴权后，用该发布物的 `createReleaseAssets` 提供静态文件。只服务静态文件，不为读取旧版 JS 再创建引擎、适配器或修改通知策略。未知或不再保留的提交返回 404，不能悄悄改成新版资源。

未固定版本的 `/codex/` 和 API 使用当前版本。已打开页面可以继续获取它原来的静态资源；已有 SSE、请求、审批、队列和传输监听器仍归宿主所有。接口 v1 内应保持兼容；不兼容变更需要新的契约版本和显式迁移。

`GET /codex-api/v1/application` 返回包版本、接口版本和 `release`，响应头另有 `X-Codex-Web-Release`。宿主应用状态、发布指针、回退命令属于宿主运维，不向浏览器增加通用执行或部署接口。
